## 2. Bugs Found & Fixed

Every bug below was discovered by an automated test, fixed, and covered by a
regression test that now passes.

| # | Bug | Severity | Found by | Fix | Regression test |
|---|---|---|---|---|---|
| 1 | `GenericHttpProvider.mapResponse` crashed on `null` array elements in the detections payload (`Cannot read properties of null (reading 'class')`) | High | `tests/unit/generic-http-provider.test.ts` | Added null/type guard filter before mapping | `filters out null/invalid detections` |
| 2 | `GenericHttpProvider` accepted detections with empty class label and negative confidence, violating the `Detection.confidence ∈ [0,1]` contract | Medium | `tests/unit/generic-http-provider.test.ts` | Reject empty class; clamp/reject non-finite confidence | `filters out null/invalid detections` |
| 3 | `config` cached env vars at import time → tests could not override env per-test AND runtime provider switching via Settings did not take effect without a restart | High | `tests/unit/generic-http-provider.test.ts` | Converted `config` to lazy getters that read `process.env` on every access; added `timeout`/`retries` fields that were referenced but missing | all generic-http tests |

| 5 | `GET /api/provider/config` returned the **raw API key** in the response body — a security leak (PATCH masked it, GET did not) | **Critical** | `tests/integration/security.test.ts` | Mask `apiKey` as `"(set)"` in GET response, matching PATCH behavior | `GET /api/provider/config never returns the raw API key` |

| 8 | SSR/CSR hydration mismatch: the theme-toggle `<Sun>`/`<Moon>` icon rendered differently on server (theme undefined → Moon) vs client (theme dark → Sun), causing a React hydration error on every page load | High | `tests/e2e/app.spec.ts` (Playwright) | Render BOTH icons and toggle visibility via Tailwind `dark:` classes — no JS conditional, identical server+client markup | `homepage loads with sidebar and no critical errors` + `no hydration errors on initial load` |

## 7. Known Issues (non-blocking)

1. **Runtime provider switching requires restart.** The `Settings` UI persists the provider config to the DB, but `getProvider()` caches the provider instance in a module-level variable. Changing `AI_PROVIDER` in the DB does not hot-swap the active provider without a process restart. *Workaround*: restart the server after changing the provider. *Documented* in `docs/AI_PROVIDERS.md` and the config module's JSDoc.
2. **Video upload metadata is placeholder.** The upload route creates a `VideoAsset` with default metadata (180s, 1280×720, 30fps) rather than probing the real file with FFprobe. *Reason*: V1 ships the mock provider; real video probing is the documented local-inference extension point.
3. **PDF export is browser print-to-PDF.** No native PDF engine is bundled. The HTML report is print-ready (verified: `@media print` rules present). *Documented* in `CHANGELOG.md`.
